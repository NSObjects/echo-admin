# Finalize Route Exposure from the Registered Route Table

Echo Admin classifies every registered `/api` route as exactly one System API Route, Bootstrap API Route, or Managed API Route. Boot owns exact method and registered Echo pattern declarations for System and Bootstrap routes; Managed is the complement. `OPTIONS`, 404, and 405 requests have no registered route identity and remain outside this classification.

Business modules keep the ordinary `Register(group, handler)` interface. After every registrar completes, boot scans `Echo.Router().Routes()`, builds an immutable manifest, rejects assembly when Managed routes exist without Route Authorization, and installs one global Echo middleware. Global middleware is required because Echo group middleware is copied into routes when they are registered. Runtime authorization uses `Context.RouteInfo()` so parameterized requests are checked against the registered pattern rather than the raw URL. A matched Managed route absent from the finalized manifest fails closed.

Access owns a code-level Managed API Route Catalog containing method, registered pattern, description, group, and permission metadata. System First Initialization persists that catalog. Runtime authorization reads the persisted row and requires the current role's explicit API grant, including for the root role; there is no `Public` or root bypass. Administrators may inspect the catalog and manage role grants but cannot create, update, delete, or import route definitions. A DB-free boot contract test compares the real registered Managed set with the access definition in both directions and rejects missing, stale, duplicate, or wrongly classified entries. Catalog changes are explicit deployment work rather than startup repair.
